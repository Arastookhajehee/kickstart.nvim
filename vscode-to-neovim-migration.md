# VS Code to Neovim Migration Worksheet

This compares `vs_code_ref/keybindings.json`, `vs_code_ref/settings.json`,
and the active Neovim config in `init.lua`, `after/plugin/user-remaps.lua`,
`lua/kickstart/plugins/*.lua`, and `lua/custom/plugins/*.lua`.

## High-Value Migration Ideas

- Keep the VS Code-style leader layer that already exists in Neovim:
  `<leader>d`, `<leader>D`, `<leader>g`, `<leader>z`, `<leader>s`,
  `<leader>w`, `<leader>r`, `<leader>h`, and `<leader>H` mostly mirror
  your VS Code habits.
- Decide what `<leader>f` should mean: VS Code uses `Space f` for
  in-buffer find, while Neovim currently uses `<leader>f` for formatting
  and `<leader>/` for in-buffer fuzzy search.
- Add a file-finder mapping if you miss VS Code `Space o` or `Space p`;
  Neovim has Telescope file search at `<leader>sf`, but the VS Code-like
  `<leader>o` and `<leader>p` meanings are currently different or absent.
- Resolve conflicting Neovim mappings before adding more: `<leader>s` is
  both document symbols and multicursor skip match, while `<leader>n` /
  `<leader>N` are both multicursor match selection and next/previous file.
- Add VS Code tab/editor index navigation if you rely on it: `Ctrl+1..9`,
  `Alt+1..3`, `Ctrl+Tab`, and Open Editors focus do not have direct Neovim
  mappings yet.
- Decide whether VS Code debug keys should be translated as-is: VS Code uses
  `F8` variants; Neovim DAP currently uses `F5`, `F1`, `F2`, `F3`, `F7`,
  `<leader>b`, and `<leader>B`.
- Replace VS Code Bookmarks with native marks if that feels enough: Neovim
  already maps `<leader>m`, `<leader>M`, `<leader>'`, and `<leader>"`;
  install a bookmark plugin only if you need VS Code-style labeled cross-file
  bookmark UX.
- Port settings that affect muscle memory first: relative numbers, rulers at
  100/120, clipboard, no format-on-save, markdown rendering, image preview,
  and Copilot disabled-by-default behavior.
- For VS Code extension-backed commands, pick Neovim equivalents deliberately:
  Television/global fuzzy search maps to Telescope/Snacks/FzfLua; Copilot maps
  to `copilot.lua` or blink/avante integration; SCM sidebars map to
  Neogit/Diffview/Gitsigns; Open Editors maps to buffers/Telescope
  buffers/Harpoon.

## Conflict / Gap Checklist

- **Format vs find**
  - Item: `<leader>f` means format in Neovim but find in VS Code.
  - Why: This is likely the biggest muscle-memory mismatch.
  - Decision: keep `<leader>f` for format and use `<leader>/` for buffer find
- **File finder vs opencode operator**
  - Item: `<leader>o` means file finder in VS Code.
  - Item: `<leader>o` means opencode operator in Neovim.
  - Why: Decide whether AI range-send or file finder wins this key.
  - Decision: keep `<leader>o` for opencode and use `<leader>sf` for files
- **Quick open missing**
  - Item: `<leader>p` means quick open in VS Code but is unmapped in Neovim.
  - Why: Easy place to add Telescope find files or buffers.
  - Decision: skip because `<leader>sf` and `<leader><leader>` cover this
- **Leader c meanings**
  - Item: `<leader>c` has several VS Code meanings and no Neovim normal mapping.
  - Why: Candidate for Copilot toggle or next change.
  - Decision: use `<leader>c` for next git hunk and `<leader>C` for previous
- **Copilot toggle missing**
  - Item: `<leader>i` toggles Copilot in VS Code but is unmapped in Neovim.
  - Why: Needs Copilot plugin if you want it.
  - Decision: skip for neovim
- **Leader n conflict**

- **Leader s conflict**

- **Debug keys differ**
